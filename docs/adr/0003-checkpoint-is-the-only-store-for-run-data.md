# The LangGraph checkpoint is the only store for run data

Everything a Run produces (structured CV, Requirements, Coverage, Changes, Evidence, scores) lives in the graph state in the Postgres checkpoint, and is read back with `getState()` through a purpose-built run view. Our own tables hold only run metadata (`runs`: id used as `thread_id`, status, timestamps, expiry, export path). We rejected mirroring the data into relational tables because it needs two copies kept in sync and cascading deletes for the privacy promise, while cross-run queries aren't needed until accounts or analytics exist. Because runs expire after 7 days, checkpoints written under an older state schema are short-lived, so state schema changes need no migration. This should be revisited when saved CVs or run history arrive.

**Re-judging after each pass.** The Match Score is deterministic, but its inputs are LLM Coverage verdicts, so applied Changes require fresh verdicts. We re-judge only the Requirements that applied Changes list as addressed and carry every other verdict over unchanged. This keeps the cost per iteration small. It can undercount a Change that helps a Requirement it didn't list, which we accept for v1; do not "fix" it by re-judging everything without weighing the extra LLM calls per iteration.

**No `remove` Change.** Changes may `replace`, `add` or `reorder` Items, never remove them. Removal is the only operation that loses the candidate's information, and reordering already pushes irrelevant content down. Revisit this if the CV template turns out to have a page limit.

**Slice 1 exception (transitional).** The graph and checkpointer do not exist until slice 4, but parsing happens in slice 1 and extraction in slice 2 needs its output. Until then `runs` carries two extra columns, `cv_text` and `jd_text`, holding the parsed CV text and the Job Description text. Slice 4 passes them into the graph as its initial input and drops the columns. The uploaded file is still never stored: it is parsed in memory and discarded (ADR 0002).
